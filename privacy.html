MusicStats Privacy Policy

Last updated: 26.11.2026

MusicStats (https://musicstatsapp.com) is an analytics tool for independent musicians. It collects statistics of the user's own songs from platforms (YouTube, Spotify for Artists, TikTok, Instagram, DistroKid) into one database and shows reports. By using MusicStats you agree to this policy.

YouTube API Services

MusicStats uses YouTube API Services. By connecting YouTube you also agree to the YouTube Terms of Service, and data received from Google is also subject to the Google Privacy Policy.

Data we access

  • YouTube (via Google OAuth): read-only access to the user's own channel analytics and video list (scopes yt-analytics.readonly and youtube.readonly): views, watch time, likes, comment counts, shares, new subscribers per day and per video, video titles, publish dates and durations, the channel name. MusicStats never publishes, changes or deletes anything on YouTube. Access is granted either in the desktop program on the user's computer or with the «Connect YouTube» button in the online version with an account.
  • Export files (CSV/ZIP) from other platforms that the user uploads.
  • Signing in to the online version (with Google): only the email and name, to recognise the user and check the invitation. We get no access to mail, files or any other Google data.
  • Suggestions to add a distributor or platform: the user's email, the chosen name, a comment and — only with separate consent — a sample export file, visible only to the MusicStats administrator and used only to build the connector; deleted on request.
  • Pro plan payments are made on a Stripe page (Stripe Payments Europe); card details are processed only by Stripe and never seen or stored by MusicStats. We store the email, the Stripe customer and subscription IDs, the plan and the date it is paid until. Payment processing follows the Stripe Privacy Policy.
  • MusicStats uses no advertising or tracking cookies; only technical sign-in cookies (Streamlit / Google Sign-In).

How data is used

Only to show the user themself their statistics: charts, tables and an insights report. Data is never sold or shared with third parties, never used for advertising and never combined with other users' data.

Where data is stored

  • In local use, data and the access token (token.json) stay only on the user's computer in musicstats.db.
  • In the online version without an account, uploaded files and the database exist only for the browser session and in a temporary server folder.
  • In the online version with an account (by invitation), the user's database is stored as a separate file in private Supabase Storage, accessible only to that user after signing in. The file name is a hash of the email.
  • If the user connects YouTube in the online version, the Google refresh token is stored encrypted in a separate file in the same private storage and is used only to fetch that channel's statistics into the user's own database: automatically every day, on sign-in or with the «Update now» button.

Visit statistics

  • MusicStats counts unique visitors to the app: the IP address and browser name are turned into a one-way hash with a key that changes every month, and only the hash is stored. The IP address itself is never recorded, and a visitor cannot be identified or matched across months. No cookies are used for this.
  • For accounts, MusicStats records the dates of first steps: sign-in, first data added, viewing the plans, returning from the payment page, payment. This is used only to see which steps are hard and to improve the service; only the administrator sees it, and it is deleted together with the account on request.

How we protect your data

MusicStats uses the following measures to protect user data, including sensitive Google (YouTube) data:

  • Encryption in transit. All data exchange — between the browser and the site, with Google APIs, with Supabase Storage and with Stripe — happens only over secure HTTPS (TLS) connections.
  • Encryption at rest. The Google refresh token is additionally encrypted with Fernet (AES-128 + HMAC-SHA256) before it is stored; the encryption key is kept separately, only in the server's protected secrets, and never appears in the code, the browser or logs. Files in Supabase Storage are encrypted at rest (AES-256).
  • Private storage and isolation. User databases and tokens are kept in private storage with no public links; only the MusicStats server can access it, using a secret key. Each user has a separate database file, which the server opens only after that same user signs in with Google.
  • Restricted access. Only the MusicStats developer has access to the server, the storage and the secrets; the accounts used to manage them are protected with two-step verification. The developer does not view user data except when the user asks for help, or when security or the law requires it.
  • Data minimization. MusicStats requests read-only scopes and stores only the statistics needed for the reports. Tokens and personal data are never written to logs.
  • Secure authorization. The return from Google after connecting YouTube is verified with a signed (HMAC) state parameter valid for 30 minutes, so no one else can link a channel to your account.
  • Incidents. In case of a data breach or unauthorized access, MusicStats will notify the affected users and the competent data protection authority without undue delay (under the GDPR — within 72 hours).

Retention and deletion of YouTube data

  • MusicStats checks that the YouTube authorization is still valid every day (and at least every 30 days).
  • When access is revoked (with «Disconnect YouTube» or in the Google account) or can no longer be refreshed, MusicStats immediately deletes the token and all YouTube statistics obtained through the connection (in any case within 30 days).
  • «Delete my data from the server» immediately deletes the user's whole database and token (in any case within 7 days of the request). The same can be requested by email. The user can download a copy first.

Use of Google user data

MusicStats' use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

How to revoke access

Disconnect YouTube in the online version at any time, or revoke MusicStats' access on the Google security settings page: https://myaccount.google.com/permissions. In local use you can also delete token.json and musicstats.db.

Політика конфіденційності MusicStats

Оновлено: 26.11.2026

MusicStats (https://musicstatsapp.com) — інструмент аналітики для незалежних музикантів. Він збирає статистику власних пісень користувача з платформ (YouTube, Spotify for Artists, TikTok, Instagram, DistroKid) в одну базу даних і показує звіти. Користуючись MusicStats, ви погоджуєтеся з цією політикою.

YouTube API Services

MusicStats використовує YouTube API Services. Підключаючи YouTube, ви також погоджуєтеся з Умовами використання YouTube, а дані, отримані від Google, обробляються і відповідно до Політики конфіденційності Google.

Які дані ми отримуємо

  • YouTube (через Google OAuth): лише доступ на читання статистики й списку відео каналу користувача (області доступу yt-analytics.readonly і youtube.readonly): перегляди, час перегляду, лайки, коментарі (кількість), поширення, нові підписники по днях і по відео, назви, дати й тривалість відео, назва каналу. MusicStats нічого не публікує, не змінює й не видаляє на YouTube. Доступ надається або в програмі на комп'ютері користувача, або кнопкою «Підключити YouTube» в онлайн-версії з акаунтом.
  • Файли вивантажень (CSV/ZIP) з інших платформ, які користувач завантажує сам.
  • Вхід в акаунт онлайн-версії (через Google): лише email і ім'я — щоб розпізнати користувача й перевірити запрошення. Доступу до пошти, файлів чи інших даних Google ми не отримуємо.
  • Пропозиція додати дистриб'ютора або платформу: email користувача, вибрана назва, коментар і — лише за окремою згодою — зразок файлу експорту. Їх бачить тільки адміністратор MusicStats; зразок використовується лише для створення конектора (читача файлів) і бонусу автору пропозиції, а потім може бути видалений. На вимогу видаляємо заявку й файл повністю.
  • Оплата тарифу Pro відбувається на сторінці Stripe (Stripe Payments Europe); дані картки обробляє лише Stripe, MusicStats їх не бачить і не зберігає. Ми зберігаємо email, ідентифікатор клієнта й підписки Stripe, тариф і дату, до якої його оплачено. Обробка платежів — за Політикою конфіденційності Stripe.
  • MusicStats не використовує файли cookie для реклами чи стеження; сайт ставить лише технічні cookie входу (Streamlit / Google Sign-In).

Як використовуються дані

Лише для того, щоб показати самому користувачеві його статистику: графіки, таблиці, звіт-висновки. Дані не продаються, не передаються третім особам, не використовуються для реклами й не поєднуються з даними інших користувачів.

Де зберігаються дані

  • Під час локального використання дані й ключ входу (token.json) зберігаються лише на комп'ютері користувача у файлі бази musicstats.db.
  • В онлайн-версії без входу завантажені файли й база існують лише протягом сесії браузера та в тимчасовій папці сервера; користувач сам завантажує свою базу собі.
  • В онлайн-версії з акаунтом (за запрошенням) база користувача зберігається в окремому файлі в приватному сховищі Supabase Storage; доступ до неї має лише сам користувач після входу. Назва файлу — зашифрований (хешований) email, а не сама адреса.
  • Якщо користувач підключив YouTube в онлайн-версії, ключ доступу Google (refresh token) зберігається зашифрованим в окремому файлі того ж приватного сховища і використовується лише для того, щоб забирати статистику його каналу в його власну базу: щодня автоматично, під час входу на сайт або кнопкою «Оновити зараз».

Статистика відвідувань

  • MusicStats рахує кількість унікальних відвідувачів застосунку: з IP-адреси й назви браузера робиться односторонній хеш із ключем, що змінюється щомісяця, і зберігається лише він. Саму IP-адресу не записуємо, відвідувача не можна впізнати й зіставити між місяцями. Cookies для цього не використовуються.
  • Для акаунтів MusicStats записує дати перших кроків: вхід, перше додавання даних, перегляд тарифів, повернення зі сторінки оплати, оплата. Це потрібно лише для того, щоб зрозуміти, які кроки незручні, і покращити сервіс; ці дані бачить лише адміністратор і видаляються разом з акаунтом на запит.

Як ми захищаємо дані

MusicStats вживає таких заходів, щоб захистити дані користувачів, зокрема чутливі дані Google (YouTube):

  • Шифрування під час передавання. Увесь обмін даними — між браузером і сайтом, із Google API, зі сховищем Supabase і зі Stripe — відбувається лише через захищене з'єднання HTTPS (TLS).
  • Шифрування під час зберігання. Ключ доступу Google (refresh token) додатково шифрується алгоритмом Fernet (AES-128 + HMAC-SHA256) перед збереженням; ключ шифрування зберігається окремо, лише в захищених налаштуваннях сервера (secrets), і ніколи не потрапляє в код, браузер чи журнали. Файли у сховищі Supabase шифруються на рівні диска (AES-256).
  • Приватне сховище й ізоляція. Бази користувачів і ключі доступу лежать у приватному сховищі без публічних посилань; звернутися до нього може лише сервер MusicStats за секретним ключем. Кожен користувач має окремий файл бази, і сервер віддає його лише після входу через Google саме цього користувача.
  • Обмежений доступ. Доступ до сервера, сховища й секретів має лише розробник MusicStats; облікові записи для керування ними захищені двоетапною перевіркою. Розробник не переглядає дані користувачів, окрім випадків, коли користувач сам просить про допомогу, або коли цього вимагають безпека чи закон.
  • Мінімум даних. MusicStats запитує лише дозволи тільки на читання і зберігає лише статистику, потрібну для звітів. Ключі доступу й особисті дані не записуються в журнали.
  • Захист входу. Повернення з Google після підключення YouTube перевіряється підписаним параметром (HMAC), дійсним 30 хвилин, щоб ніхто інший не міг підключити свій чи чужий канал до вашого акаунта.
  • Інциденти. Якщо станеться витік чи несанкціонований доступ до даних, MusicStats повідомить користувачів, яких це стосується, і відповідний орган із захисту даних без зайвої затримки (за GDPR — протягом 72 годин).

Зберігання й видалення даних YouTube

  • MusicStats перевіряє, що доступ до YouTube дійсний, щодня (і щонайменше раз на 30 днів).
  • Якщо доступ відкликано (кнопкою «Відключити YouTube» або в акаунті Google) чи його більше не можна оновити, MusicStats одразу видаляє ключ доступу й усю статистику YouTube, отриману через підключення (у будь-якому разі — не пізніше ніж за 30 днів).
  • Кнопка «Видалити мої дані з сервера» одразу видаляє всю базу користувача й ключ доступу (у будь-якому разі — не пізніше ніж за 7 днів після запиту). Те саме можна зробити, написавши на адресу нижче. Перед видаленням користувач може завантажити копію своєї бази.
